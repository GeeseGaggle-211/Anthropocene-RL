# Anthropocene training: findings and architectural decisions

Reviewed by the root architecture reviewer, 23 October 2026. Implementation was delegated to GPT-5.6 Sol x-high; conclusions below are the root review. This is a completed findings report, not a claim that every historical causal link or proposed repair has been established.

## Bottom line

Do not advance the unchanged learner to round 4. The evidence supports repairing input conditioning and critic target initialization first, then the PPO sampling/update controls. Replacing welfare/trade with QoL/population is a defensible objective simplification, but it does not repair the input defect: population and QoL predictions also respond to it.

**Recommended target architecture: actor-owned labor allocation → side-effect-free feasibility validation → penalized rejection with one reallocation retry → minimal safe fallback only if the retry fails.** Retain every rejected attempt in training, with a dedicated feasibility-cost critic and an explicit actor penalty. Routine rescue of avoidably invalid allocations is no longer the recommended interface. The opt-in implementation now passes the isolated correctness and native collector checks in section 7; calibrated training and performance acceptance remain outstanding. Historical results below do not measure this replacement.

The strongest demonstrated mechanism is this: features that were constant during normalization fitting become nonconstant in closed-loop play; division by a 0.001 standard deviation magnifies them into hundreds or thousands. The critic can then assign large value differences to previous-decision bookkeeping even when immediate physical outcomes are identical. Independent continuation estimates do not support the magnitude of those predicted gains in the tested state.

## 2. The input/critic defect is concrete

The T3 checkpoint's previous-decision normalizer uses mean zero and standard deviation approximately 0.001 for several affected coordinates, without the guard/dead-feature handling. In the no-learning sensitivity probe:

- Core 47, previous requested development budget, reached a normalized magnitude of approximately 626.
- Core 53, previous compiler intervention count, reached approximately 1,792.
- In the new six-turn instrumented validation, core 54 (previous elapsed years) reached 3,044.522. All inputs were finite: a nonfinite-only alarm would miss the problem.

A paired first action changed only development budget. Its immediate physical-event quantities, ending population, QoL and person-years were identical; field-development grants were zero in both branches. Yet aggregate successor predictions changed by +87,285 welfare and +106,153 population-years. Replacing only the previous-decision input block reproduced nearly all that sensitivity. The compiler-intervention coordinate dominated the tested substitutions; the effects are nonlinear and must not be added as independent attributions.

After the same complete second action, the branches had identical observations, fingerprints and physical events, and the critic differences were zero. This isolates a transient input-history sensitivity in that state. It does not by itself prove that history has no legitimate predictive value or quantify its historical contribution to all T3 losses.

## 3A. Does the compiler hide actor mistakes and impair learning?

**Finding: it demonstrably hides raw-request infeasibility from outcome-only feedback, and the current critic creates a misleading learning signal around that repair. This is a supported failure mechanism, not proof that compiler intervention alone caused the aggregate T3 regression.** An oversized or unstaffable request can be repaired into the same executed allocation as a smaller request. The actor is then rewarded for the repaired outcome; it never experiences the hypothetical outcome of executing its raw request. This can be desirable safety behavior, but it means realized welfare cannot, by itself, teach the actor which of those requests was feasible. An infeasible request is not automatically an avoidable actor mistake: some limits can depend on competition or information unavailable at decision time.

The source and existing trace establish the following chain:

1. **Large amounts of requested control do not survive compilation.** In the 63-decision validation, all 63 positive development-budget requests differed from the accepted budget; 55 were accepted as zero. All 51 active field-retention requests and all eight active herd-retention requests also differed from their accepted values (absolute tolerance 1e-8). These differences include ordinary quantization and legal/physical constraints; not every difference is a compiler bug.
2. **The learning objective does not directly penalize request repair.** PPO stores the sampled requests and their log probabilities, then uses rewards from the resolved simulator outcome. `_cost` concerns small surviving settlements, not intervention count or requested-versus-granted work. Reward shaping charges sampled economy-mix changes and voluntary commitment breaks, not general compiler correction. Teacher regularization remains a separate influence. Thus there is no explicit feasibility-learning signal merely because a request was repaired.
3. **The frozen-state probe shows actual physical aliasing, not just a statistical association.** Different development requests produced identical immediate physical events and demographic outcomes; after the same second action the worlds' fingerprints and observations matched. The request difference therefore did not buy the immediate physical benefit suggested by the critic.
4. **Repair bookkeeping supplies a false-looking value distinction.** Previous requested development and compiler-intervention count enter the next observation through the badly scaled history features. The paired successor critic moved by roughly +87,285 welfare, despite the identical immediate physical outcomes. The independent continuation comparison did not support the predicted benefit's magnitude. Consequently, a compiler-mediated history difference can enter TD/GAE as apparent improvement even when the underlying intervention did not improve immediate execution.

This is more precise than “the compiler prevents learning.” A projection many requests share can flatten the genuine consequence signal; the misconditioned critic then invents distinctions in that flat region. Removing the projection would expose physical mistakes but would not repair that critic. Conversely, a calibrated critic could learn the outcome of the actor-plus-compiler system without needing to punish every harmless repair. No compiler-off outcome comparison was run, and this report does not label every rejected request economically inferior to every accepted alternative.

### Required change: explicit rejection and fallback-repair costs

The user's intended behavior is stronger than optimizing the repaired outcome: **the actor should learn to submit feasible requests.** Make avoidable rejection and final fallback repair explicit training costs within the bounded retry protocol below. A critic that merely predicts welfare will not supply this missing preference, and training a feasibility-cost critic without coupling it to the actor will not change the policy.

1. **Measure the cost at the validator/compiler boundary.** Charge each avoidable rejection a positive base cost plus a bounded, reason-specific violation-severity term, normalized in the relevant resource units. Measure predictable overcommitment of labor/materials and choices inconsistent with decision-time feasibility information. A final fallback may incur a separately declared rescue surcharge, but must not count the same violation severity twice as both rejection and repair. Sum costs across attempts; do not divide them by the number of attempts. Coefficients, tolerances and any cost budget are versioned design parameters, not claimed optima. Do not use raw diagnostic event count or the ambiguous `lower-return ray` label as the target.
2. **Separate avoidable errors from other intervention.** Exclude inactive-head defaults, intended commitment holds, ordinary quantization within a stated tolerance, exogenous competition not observable at decision time, and discretionary native-policy overrides of otherwise feasible actions. Those remain logged. Where avoidability cannot be established, label it unknown rather than invent an actor fault; expose predictable constraints in the observation so the actor has the information needed to improve.
3. **Add a dedicated feasibility-cost value head.** Train it on observed rejection/fallback costs and their discounted returns, with appropriate initialization and calibration. Condition both task-value and feasibility-cost estimates on attempt state, including feedback and retries remaining; preserve the existing small-settlement cost separately. This head estimates future compiler dependence; it must not fabricate negative QoL or population outcomes to represent rejection or repair.
4. **Couple that cost to the actor.** Subtract its cost advantage from the task advantage: conceptually `A_policy = A_task - lambda_feasibility * A_feasibility_cost`, alongside the existing constraint terms. Use a defined, stable cost scale and a reviewed fixed coefficient or constrained-budget multiplier; do not independently standardize away the meaning of the cost budget. An action requiring more avoidable correction than expected then receives a negative contribution even when a retry or fallback rescues its physical outcome. Task returns remain essential so “request nothing” does not become the sole objective.

The immediate measured cost must enter the target; this must not become another head trained only to reproduce its own bootstrap. Retain per-head cost contributions in the trace so any competition with QoL/population is visible. Fix the defective input normalization alongside this change: otherwise the new critic can inherit the same spurious history sensitivity. This is the report's recommended learning contract, not an optional logging improvement. Its subsequent opt-in implementation and correctness checks are described in section 7; performance remains unvalidated.

### Recommended architecture: labor head with bounded reject-and-reallocate

**Move discretionary allocation into an explicit actor labor head, and require the actor to correct avoidably infeasible plans before execution.** The present service-cap interface does not express the actor's desired labor tradeoffs. A second head that merely duplicates the existing cultivation/herding/fishing development mix would not solve that problem. The compiler remains responsible for physical feasibility, not economic preferences.

Recommended contract:

- **User-revised head, 23 October:** the actor chooses a masked specialty softmax multiplied by the settlement's full controllable population, including an explicit idle category. Previous role assignments and native planned reservations do not reduce the reallocatable pool. Deterministic largest-remainder rounding preserves integer headcount and is reported, not penalized. This replaces the earlier residual-budget/task-bundle output recommendation.
- Each multi-output specialty receives actor-controlled masked activity shares, including idle. Keep food versus material gathering, field operation versus expansion, and individual craft goods explicit. Native execution may enforce recipes and material conservation but must not add prerequisite gatherers, reassign unused workers, or choose its preferred production mix. Staffing a material-constrained specialty remains legal: idle work and reduced production are outcomes to learn from, not a failed promise of goods the actor never requested.
- Specialty and specialty-activity tokens use stable identities, capability/recipe features, availability masks and shared scoring heads. Each specialty aggregates its own activities; activity decisions retain that ownership plus global settlement/resource context. Today's catalog size is not a fixed output-layer size. Adding specialties extends the versioned registry; explicit checkpoint compatibility/migration prevents silent ordinal reinterpretation. Extension tests must cover additional specialties/activities, reordered paired tokens, and absent padded rows without changing existing meanings or producing nonfinite values. New resource types or feature semantics can require an explicit encoder migration; token compatibility is not evidence that an untrained specialty is ready. Fractional activity worker-time remains available within rounded specialty headcounts. Harvest versus development must also be explicit for fishing, so unused harvest labor cannot silently fund capital.
- Retire or redefine overlapping development-budget/mix outputs so two heads do not independently command the same workers. Service outputs can remain quotas/targets, not a second hidden labor allocator. Keep non-labor decisions fixed during a labor retry, and validate the complete plan including their resource reservations; do not use a retry to silently resample movement, trade or commitment choices.
- The compiler validates the submitted allocation before any execution. Minor rounding within a declared tolerance is repaired deterministically. Avoidable hard violations trigger rejection, not routine rescue. Final fallback after the retry is deterministic and minimally distorting: no native return ranking, explicit residual/idle labor, and actor-directed priorities for any permitted reassignment. Unexpected resolution-time competition may require safe repair without labeling it an avoidable actor fault.
- Expose proposed, accepted, fallback-projected and executed allocations separately, with reason-specific rejection/repair magnitudes. Apply the dedicated feasibility-cost critic and actor penalty above. Do not penalize raw intervention count: it conflates harmless rounding, external shortages and deliberate safety rules.
- Keep PPO likelihoods tied to the action actually sampled. Do not substitute the projected action into the old request distribution's log probability: multiple requests can map to that same allocation. Prefer action parameterizations that are feasible by construction where practical.

#### Requested versus executed allocation: actor input

The actor and task/cost critics must be able to distinguish the previous **raw requested**, **compiler-accepted**, and **actually executed** allocation. Supply these in matching units and stable activity order, together with signed deltas (`accepted - requested`, `executed - accepted`, `executed - requested`), validity/activity masks, reason/avoidability categories, fallback status and parent decision identity. Keep assigned labor, actual work and goods receipts separate: a copied service directive is not an execution receipt. Use bounded, versioned normalization; missing execution evidence is unavailable, not zero work.

For the specialty head, retain fractional requested headcounts, rounded integer assignments, activity worker-year budgets and measured consumed work. Resource tokens report gross production, input consumption and known shortage reasons separately from trade and net inventory changes. If a forecast is supplied, label its assumptions and compare realized output in the same resource units; it is not an actor-requested output quantity. Material-starved workers must not disappear into hidden compiler reassignment.

Retain the initial and retry requests in the attempt ledger and identify the last sampled proposal as the direct comparator for final execution. During a retry, expose only the rejected request and already-known validation feedback. Final execution becomes input at the successor physical decision, never before it occurs. Outcome targets use the real resolved transition, attributed through the original sampled-action likelihoods. The allocation delta explains compiler mediation and supports avoidable-feasibility learning; it does not manufacture the counterfactual outcome of an unexecuted raw request or make every execution shortfall an actor mistake.

#### Bounded decision protocol

Use **two proposals at most: the initial allocation and one retry**. This is the recommended initial contract, not an empirically optimized retry count.

1. **Propose.** From the decision-time observation, the actor selects the labor allocation and other enabled decisions. Provide available workforce, known material/technology limits, declared reservations and feasibility masks.
2. **Validate without side effects.** Check the full resource plan. Validation must not advance the world, consume resources, commit partial assignments, mutate persistent compiler state or draw from simulator RNG. Use a consistent decision boundary across villages; do not reveal hidden competitors' future actions as rejection feedback.
3. **Accept or reject.** A feasible plan proceeds to execution. An avoidably infeasible plan receives its immediate rejection cost and structured feedback: constraint identifier, requested versus available amount, implicated activities and one retry remaining. Feedback describes the violation, not a hidden native planner's preferred allocation.
4. **Reallocate once.** The actor sees the unchanged physical state plus the rejection feedback and remaining-attempt count, and proposes a new labor allocation. The feedback makes this a distinct policy state even though no simulated time has elapsed. No optimizer update occurs inside this decision loop.
5. **Execute exactly once.** Execute the accepted retry, or, if it is also invalid, charge its rejection cost and invoke the minimal safe fallback with the declared rescue surcharge. With a feasible idle/reserve residual, fallback must terminate the decision without an unbounded search or another actor retry. Advance the simulator only after all required plans are ready.

Reject predictable actor-controlled overcommitment; minimally repair ordinary rounding; resolve unobservable external shortages safely; never reject a feasible allocation merely because the native heuristic prefers another one.

#### How every rejected attempt enters training

**Treat attempts as explicit transitions in an augmented decision process, not as discarded action samples.** The current one-row-per-simulation-step collector is insufficient for this protocol and must be changed with the actor/critic interface.

- Retain each attempt's parent decision ID, attempt index, remaining retries, observation/feedback, masks, sampled action or latents, behavior-policy log probability and version, task/cost value predictions, validator result, reason-specific cost, and successor attempt or world-transition ID. Rejected attempts are not terminal unless the actual episode terminates. Retain the final compiler fallback as an execution record, not as a fictitious actor action.
- A rejected-attempt transition has **zero immediate environmental reward, positive feasibility cost and zero elapsed simulation time**. Bootstrap from the feedback-conditioned retry state, not from the pre-rejection state. Use discount 1 on internal retry edges; keep the physical-time discount on the sole simulator-advancing edge. Use trace-continuation factor 1 across retry edges so inserting a retry does not add an artificial GAE attenuation; apply the ordinary temporal lambda at physical transitions.
- The accepted attempt, or the final rejected attempt followed by fallback, leads to the one real simulator transition. Record QoL/population/trade reward and elapsed years **once** on that edge. Returns propagate that eventual outcome back through prior attempts together with their accumulated rejection costs; do not copy the immediate reward into every retry row. The final rejected attempt can carry both its rejection/fallback cost and the later executed outcome.
- PPO computes a separate likelihood ratio for each sampled attempt, using that attempt's stored observation, mask and old log probability. Train only heads actually sampled on that attempt: fixed non-labor choices are not scored again on a labor retry. All attempts must contribute to the policy update; do not select only accepted proposals, renormalize the behavior distribution to “accepted actions,” or relabel fallback output as the sampled action.
- Preserve the objective per physical decision: aggregate attempt loss contributions with a parent-decision-based denominator rather than averaging away extra rejection costs when more retries occur. If minibatches use attempt sampling, use weights consistent with that declared objective. Report rollout coverage in both physical decisions and attempts. Charge existing mix-change/commitment shaping once according to its physical-decision contract, not once per retry, and keep teacher/entropy weighting explicit so a retry cannot accidentally multiply unrelated penalties.

Required implementation acceptance checks: rejection leaves world/resource/simulator-RNG state unchanged; every decision executes once and terminates within two proposals; rejected rows survive collection and PPO batching; feedback/retry state reaches the actor and task/cost critics; a synthetic paired case with equal eventual task outcome but one extra avoidable rejection has a strictly lower combined return; fallback is feasible and not mislabeled as an actor sample; and no task reward, shaping cost or violation severity is duplicated. These are correctness checks for the recommended architecture, not claims that it has already improved welfare.

**Implementation order:** repair normalization/value conditioning; correct constraint visibility, reason attribution and the late-priority inconsistency; then introduce the labor head, bounded validation loop, attempt-aware collector and feasibility-cost learning as one versioned change. Deploying the head without the attempt records or penalties would recreate the masking problem. The intended benefit is clearer actor authority and an explicit cost for dependence on rescue; improved welfare remains unproven. The original recommendation amendment did not itself change or run the simulator; subsequent authorized implementation is described in section 7 and must not be confused with the historical telemetry validation in section 6.

## 4. Why the learner may reinforce the wrong signal

**Critic target anchoring is inadequate.** Scalar-to-vector initialization copies the encoder and welfare head; other heads begin as newly initialized linear layers. The default five-iteration warmup uses bootstrapped targets. A warmup count is not evidence that each head predicts independent returns. With distorted inputs, self-bootstrapping can propagate a wrong estimate into the advantage that trains the actor. The independent probe demonstrates the resulting prediction problem in one state; it does not prove that initialization alone caused the final checkpoint's error.

**Minibatch coverage is defective for an intended shuffled epoch.** The implementation redraws a permutation for each minibatch. In the observed epoch, 64 draws visited only 41 of 63 transitions: 23 repeat draws and 22 unvisited transitions. This needlessly adds sampling noise and makes an epoch's apparent coverage misleading.

**The update limiter observes the policy before the current update.** The first minibatch's pre-step KL was zero, while the bounded 16-row post-step nonnegative KL estimate was 0.06086 (configured default target 0.03). A pre-step check cannot prevent that same update from crossing its target. This is a sampled stability diagnostic, not exact full-policy KL or proof of a historical T3 overshoot.

The 16-row action audit found four negative-advantage actions reinforced and five positive-advantage actions suppressed. Shared parameters, teacher/entropy losses and Adam can produce this; the signs alone do not prove implementation error or independently harmful updates. Critic-head encoder gradient cosines in this probe were mostly positive or near zero—not evidence that severe auxiliary-head gradient conflict is the main problem. Actor and critic encoders are separate.
